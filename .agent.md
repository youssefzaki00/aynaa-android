# Ainaa Android Project - Agent Navigation Guide

Welcome! This is a core overview designed specifically for AI agents to understand the purpose, architecture, and technology stack of the Ainaa Android App.

## Project Purpose
Ainaa is a parental control / blocker and focus application. It actively monitors device usage via Android's Accessibility Services to prevent the use of blocked apps or viewing blocked keywords (especially within web browsers and social media). The app also protects itself against being disabled or uninstalled by analyzing the screen's UI tree and showing lock screens over dangerous system activities.

## Technology Stack
- **Language**: 100% Kotlin
- **UI Framework**: Jetpack Compose (`ui/` package)
- **Architecture**: MVVM + Clean Architecture principles (Layers split into `domain`, `data`, `ui`, `viewmodels`).
- **Dependency Injection**: Koin (Configuration inside `di/Di.kt`)
- **Networking**: Ktor Client (`data/remote/KtorRepo.kt`)
- **JSON Parsing**: `kotlinx.serialization`
- **Scripting / Execution**: Mozilla Rhino JS Engine (used to run JavaScript policy scripts against Android UI trees to detect complex evasion patterns).

## Core Project Structure
The core logic resides under `app/src/main/java/com/mafazaa/ainaa/`:
- `data/`: Contains Local (`SharedPrefs`), Remote (`KtorRepo`), and Models.
- `domain/`: Contains interfaces for repositories (`RemoteRepo`, `ScriptRepo`), and core models.
- `di/`: Dependency Injection wiring via Koin.
- `helpers/`: Utilities like `ScreenAnalyser` (to map UI nodes) and `LockOverlayManager` (to show blocking overlays over illicit content).
- `service/`: Central active component:
  - `MyAccessibilityService.kt`: The brain of the real-time blocking system. It hooks into `onAccessibilityEvent`, checks open applications, scans screen text for `blockedWords`, evaluates layout trees using JS scripts, and triggers window blocks.
- `ui/`: Compose-based Android UI (contains domains like `protection`, `overlay`, `support`, `dialog`).
- `utils/`: Includes `Constants.kt` which hosts essential system variables, hardcoded JWTs, app lists, and JS heuristic scripts (`defaultCodes`).
- `viewmodels/`: ViewModels like `AppViewModel.kt` managing states and bridging UI with Repositories.

## Key Patterns to Note
1. **Dependency Injection**: Dependencies are injected largely by Koin (`by inject(Class::class.java)` in non-compose classes, and constructor injection inside ViewModels). When adding new repos or managers, ensure they are strictly configured in `di/Di.kt`.
2. **Settings state**: Shared states and settings (like the blocked apps list, blocked word list, downloaded app updates) are stored locally in `SharedPreferences` managed manually via delegates in `data/local/SharedPrefs.kt`.
3. **Screen Analysis**: To block uninstallation or changing access permissions, `ScreenAnalyser` captures UI bounds and classes, and maps them into an internal tree model. These trees are processed against string-based JS scripts (in `Constants.kt`) mapped to specific devices (Xiaomi, Samsung, Realme).
4. **Dependencies Catalog**: Gradle is configured using version catalogs (`libs.*`). If adding dependencies, look first for the `gradle/libs.versions.toml` file to implement it natively.

## How to proceed with updates
- When dealing with **UI**, find the specific compose function in the `ui` module.
- When dealing with **Blocking logic**, examine `MyAccessibilityService.kt` and `Constants.kt`, along with `helpers/LockOverlayManager.kt`.
- When dealing with **Data loading/caching**, examine `data/remote/KtorRepo` or `data/local/SharedPrefs`.
